NL2RepoBench Architecture

NL2RepoBench 架构总览

A 0-to-1 repository-generation benchmark that drives OpenHands agents in headless batch mode, then grades each generated repository inside a clean Docker image with the agent-written test files stripped out.

面向「从 0 到 1 生成可运行代码仓库」的评测基准。以 headless 批处理方式驱动 OpenHands 代理，再将生成结果放入干净的 Docker 镜像中评分 —— 代理自己写入的测试文件会被先剥离掉。

Overview 总览 System architecture 系统整体架构

The benchmark is a fan-out pipeline. main.py loads every task descriptor under test_files/, expands them by model into AppData jobs, and submits them to a ThreadPoolExecutor. Each worker drives one OpenHands container to generate a repo, then a second clean container to grade it. All container lifecycle goes through python_on_whales on the host Docker daemon.

整体是一个扇出式流水线。main.py 加载 test_files/ 下所有任务，再按模型展开成 AppData 作业，丢给 ThreadPoolExecutor。每个 worker 会先启动一个 OpenHands 容器生成代码，再启动一个干净的容器进行评测。所有容器生命周期都通过 python_on_whales 走宿主机的 Docker 守护进程。

Pipeline 流水线 End-to-end task lifecycle 单任务全生命周期

StepWhereWhat happens 步骤位置动作
0 · Load test_data_service.read_all_test_data Walks test_files/. For each subdir, picks up *.txt (expected count), *commands*.json (pytest cmds), *files*.json (strip list), start.md (spec). Stuffs them into the module-level test_data_list. 0 · 加载 test_data_service.read_all_test_data 遍历 test_files/。对每个子目录，分别识别 *.txt（期望用例数）、*commands*.json（pytest 命令）、*files*.json（剥离清单）、start.md（需求文档），统一塞入模块级 test_data_list。
1 · Plan start_openhands Reads config.json. Expands every (model, proName) into an AppData, assigning port = 3000 + index. Submits all to a ThreadPoolExecutor (default 30). 1 · 规划 start_openhands 读取 config.json。把每对 (模型, proName) 展开成一个 AppData，端口按 3000 + 序号 顺次分配，全部提交给 ThreadPoolExecutor（默认 30）。
2 · Stage start_app Creates workspaces/<proName>_bo1/workspace/, copies start.md in, renders config.template.toml with the model's llm.<sanitized> section. 2 · 准备 start_app 建立 workspaces/<proName>_bo1/workspace/，把 start.md 复制进去；渲染 config.template.toml，填入该模型的 llm.<sanitized> 配置段。
3 · Generate openhands-app-<port> OpenHands runs headless, told to implement the project from start.md. It mounts the host's Docker socket and spawns its own runtime:0.56-nikolaik sibling. The driver polls container.reload() every 5 s until the auto-removed container disappears. 3 · 生成 openhands-app-<port> OpenHands 以 headless 方式运行，按 start.md 实现项目。它挂载宿主机的 Docker socket，并据此拉起一个兄弟容器 runtime:0.56-nikolaik。驱动每 5 秒轮询一次 container.reload()，直至自动回收的容器消失。
4 · Strip post_processor Zips the workspace as evidence. Then deletes all packaging files and every path listed in pyTestFileList — preventing the agent from "passing" by including a self-written copy of the test cases. 4 · 剥离 post_processor 先把 workspace 打成 zip 作为留证；然后删除所有打包文件以及 pyTestFileList 中列出的路径 —— 防止代理通过自带一份测试用例来"骗分"。
5 · Build build_image Writes a one-shot Dockerfile that FROM ghcr.io/multimodal-art-projection/nl2repobench/<proName>:1.0 and COPYs the cleaned workspace. Tags it python-test-<task_uuid>. 5 · 构建 build_image 生成一个一次性 Dockerfile：FROM ghcr.io/multimodal-art-projection/nl2repobench/<proName>:1.0，再 COPY 清理后的 workspace，最终打标签为 python-test-<task_uuid>。
6 · Grade run_test_commands Boots that test image (tail -f /dev/null), runs each command in testShell, captures stdout. Regex scans for N passed / N failed / N error, divides passed by the count from the .txt file. 6 · 评测 run_test_commands 启动该测试镜像（tail -f /dev/null 常驻），依次执行 testShell 中的命令并捕获标准输出。用正则匹配 N passed / N failed / N error，最终用 passed 除以 .txt 文件里的总数。
7 · Persist result/<id>.json Aggregated record per task — status, score, pytest breakdown, container metadata, paths. Per-task log lands in workspaces/<id>/log.log. 7 · 落盘 result/<id>.json 每个任务一份汇总记录 —— 状态、分数、pytest 拆分、容器元信息、各类路径。每任务日志另落在 workspaces/<id>/log.log。

Design 设计 Why it looks like this 为什么是这样设计的

Pure parallel fan-out, no work queue 纯并发扇出，无消息队列

There is no broker, no DB, no shared state beyond the file system. main.py populates a module-level list, then a ThreadPoolExecutor sprays start_app futures at it. Each task is fully isolated by its workspaces/<id>/ directory and its host port.

没有 broker、没有数据库，除了文件系统之外没有共享状态。main.py 填好一个模块级列表，ThreadPoolExecutor 把 start_app 一次性扇出。每个任务靠自己的 workspaces/<id>/ 目录和宿主端口完全隔离。

  • Concurrency cap = max_pool_size (default 30).
  • Ports allocated positionally: 3000 + index — collides with anything else on those ports.
  • Failures of one task never block another, but also don't get retried.
  • 并发上限 = max_pool_size（默认 30）。
  • 端口按序号分配：3000 + index —— 与同段已占用端口会冲突。
  • 单任务失败不会阻塞其他任务，但也没有自动重试。

Two Docker layers, sibling not child 两层 Docker，兄弟非父子

The OpenHands container is given /var/run/docker.sock. When it spawns its runtime sibling, that container is created on the host daemon — not nested. The host's workspaces/<id>/workspace/ is the only shared surface between the agent's runtime and the later grading container.

OpenHands 容器拿到了 /var/run/docker.sock，再去拉起 runtime 容器时，是直接在宿主的 daemon 上创建的兄弟容器，并非嵌套子容器。代理的 runtime 与后续评测容器之间，唯一共享面就是宿主上的 workspaces/<id>/workspace/。

  • Two image versions are hard-coded — keep them in lockstep when upgrading.
  • Multi-host runs need shared FS (NFS) or pre-staged files.
  • The agent prompt itself is hardcoded in openhands_app.py.
  • 两个镜像版本是写死的，升级时必须同步更新。
  • 多机执行需要共享文件系统（如 NFS），或者提前把文件预置到目标机器。
  • 给代理的 prompt 本身硬编码在 openhands_app.py 中。

Anti-cheat by deletion, not sandboxing 靠删除而非沙盒来反作弊

The grader doesn't try to detect copied test cases. Instead it deletes the entire pyTestFileList after generation — whatever the agent wrote into those paths is gone before the test image is built. The agent never sees the real test files at all; only start.md hints at the API surface.

评测端并不尝试检测代理是否抄袭测试用例，而是直接在生成结束后把整份 pyTestFileList 删除 —— 代理写在那些路径下的任何内容，在构建测试镜像之前就消失了。代理从来看不到真正的测试文件，只能从 start.md 推测 API 形态。

  • Also strips setup.py, pyproject.toml, requirements*.txt, lockfiles, etc.
  • The reference image must already contain the real test files and their deps.
  • Scoring is regex over pytest stdout — fragile to non-standard reporters.
  • 同时还会清除 setup.py、pyproject.toml、requirements*.txt、锁文件等。
  • 参考镜像必须自带真实测试文件及其依赖。
  • 评分依赖对 pytest 标准输出做正则 —— 对非标准 reporter 比较脆弱。

Filesystem as the result store 文件系统即结果库

There is no result DB. Every artifact is a file rooted at workspaces/<id>/ and result/<id>.json. only_test.py exploits this — you can re-run grading on any prior workspace by re-entering the post-processor with the same id.

没有结果数据库。所有产物都以文件形式放在 workspaces/<id>/ 与 result/<id>.json 下。only_test.py 正是利用了这一点 —— 对任意旧 workspace，只要用相同的 id 重新进入后处理流程即可重新评分。

  • workspaces/<id>.zip is the evidence snapshot, captured before file stripping.
  • Rotating harness log in logs/application.log (10 MB × 5).
  • Re-running with the same proName overwrites the previous workspace.
  • workspaces/<id>.zip 是「剥离前」的证据快照。
  • 主进程日志在 logs/application.log 滚动保留（10 MB × 5）。
  • 用相同 proName 重跑会直接覆盖上一次的 workspace。
